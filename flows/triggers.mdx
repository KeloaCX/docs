title: "Triggers"
description: "Every event that can start a flow, and how to scope it."
---

A **Trigger** node is where every flow begins. Each flow has exactly one Trigger.

## Reply flow events

| Event | Fires when |
| --- | --- |
| **New conversation (first message)** | The message is the first customer message in the conversation. This is the default. |
| **Every customer message** | Any customer message in the conversation. |
| **Conversation reopened** | A customer message reopens a solved conversation. |
| **New contact (first ever message)** | The message is the contact's first message ever, across all their conversations. |

You pick one event per flow.

**Every customer message** runs the flow on each message of a long conversation, so a Message node in it answers every time. Use **New conversation** when the flow should act once per conversation.

## Follow-up flow events

A follow-up flow starts on something your team did, not on a customer message:

| Event | Starts when |
| --- | --- |
| **When your team replies** | A teammate's email reply reaches the contact. Use a Condition after it to pick which replies get follow-ups. |
| **Started by hand from a ticket** | A teammate clicks **Start follow-up** on the conversation. |

See [Follow-up flows](/flows/follow-up-flows) for both.

## Channel scoping

By default a reply flow's trigger fires on **Any channel**. Pick one channel to scope it:

- Web chat
- Email
- WhatsApp
- Instagram
- Messenger
- Telegram
- Slack

The list shows the channels connected to your workspace. This is how you build channel-specific flows — different greetings, different routing, different after-hours handling.

Follow-up flows have no channel setting: they only run on email conversations.

## Which conversations a reply flow sees

A reply flow belongs to one AI agent and runs inside that agent's reply: only in conversations the agent answers, and only while the AI is answering. Once a teammate has taken the conversation over (a hand-off, a teammate's reply, or a teammate assigning it to someone), neither the AI nor the flow runs until the conversation is solved or closed.

A published flow without an agent never runs. The flow list shows it as **Published, but not running: no agent**.

## Timing

A reply flow runs **before** the AI agent replies:

- If the flow sends a **Message**, that message is the reply. The AI doesn't answer that message as well.
- If the flow hands off, the conversation goes to your team. Without a Message before the Handoff, the AI agent writes a short acknowledgement for the contact.
- If the flow ends without sending anything (for example an **Otherwise** output that isn't connected), the AI answers as usual.

## One reply flow per agent

Each AI agent runs one reply flow. When you publish a reply flow, the agent's other published reply flow moves back to draft, and Keloa tells you which one. To combine several routes, build them into one flow with Condition or Intent branches.

Follow-up flows work differently: several can be live side by side. See [Follow-up flows](/flows/follow-up-flows#how-a-follow-up-starts).

## Disabling a flow

Click **Unpublish** to stop a flow without deleting it. It goes back to draft; **Publish** puts it live again.
